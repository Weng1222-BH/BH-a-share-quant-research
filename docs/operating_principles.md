# 教学与项目运行原则

## 1. 目标、范围与工具

项目目标是从零学习 A 股量化，逐步完成数据分析、策略回测、科学验证、因子研究、机器学习预测、模拟盘验证，并形成 GitHub 与简历成果。

主线为 Stage 0–7，具体名称和目标见 [roadmap.md](roadmap.md)。当前工具主线为 **Python + AKShare + RQAlpha**，后期按需要引入 Qlib，暂不提前引入复杂交易系统。工具使用前核验实际版本、接口与数据条件；文档中的选型不代表环境已安装或功能已验证。

此次初始化只维护项目管理文件和后续目录，不创建实际策略代码，不提前执行 Stage 0 教学。未来学习与研究按真实进度开展；模拟盘不等于实盘，也不自动授权真实资金交易。

## 2. 事实与进度来源

项目事实优先级：

**GitHub 实际代码/结果 > docs/progress.md > 研究报告与 Session 产物 > 聊天记录 > 模型记忆**

[progress.md](progress.md) 是项目唯一真实学习进度源。其他文档维护目标、规则、计划或证据，不另建一份竞争性的“当前进度”。聊天中的完成声明必须经实际证据核对后写入进度；模型记忆不能覆盖仓库事实。

若来源冲突，先核验实际代码、结果、执行条件和适用范围，再更正 progress.md 及受影响文件，记录冲突、证据和更正原因。实际代码可以证明产物存在，但不单独证明学习者已掌握知识或通过 Gate。规划完成、创建文档和预留目录不算学习完成。

保留不冲突的已有内容，只修改与已确认规则冲突或此次任务必要的部分，不修改无关内容，不抹去未通过测验、异常和路线调整历史。

## 3. 学习层级与 Session

采用 **Stage → Substage → Session → Gate**。

每个 Stage 按学习结果动态拆分约 2–4 个 Substage，每个 Substage 由若干 Session 构成，结束时设置正式 Gate。不要一次性固定 Stage 0–7 的全部微观计划；在接近执行时根据表现与项目条件规划必要范围。

Session 默认采用 **引子 → 案例 → 必要知识 → 实践 → 复盘**：

- 引子：用问题、预测或诊断了解已有理解，明确本次任务。
- 案例：从已学或当前可理解的案例出发，暴露认知缺口。
- 必要知识：只补充完成当前任务真正需要的概念与机制。
- 实践：让学习者分析、操作、判断或实现，保留可检查的过程与结果。
- 复盘：解释结果、错误、修正及仍未解决的问题，确定下一步。

避免持续单向讲授。Session 内穿插短即时检查，分别观察理解和实操，不以“听过了”或“模型写好了”代替掌握。Stage 0 的操作可以是案例分析、判断或研究流程练习，不强制提前写策略代码。

每次 Session 开始前先读取 progress.md，核对前次产物；若有待检查的 Transfer Task，必须先检查其完成和应用情况，再进入新知识。Session 时长和周投入预算按 progress.md 弹性安排，不按固定日历自动升级阶段。

## 4. 旁支问题分流

| 类型 | 当场处理 | 留痕与后续 |
| --- | --- | --- |
| 当前任务必须理解 | 当场解决，确认能继续当前任务 | 在当前学习记录记录问题、解释与理解检查 |
| 相关但非必要 | 简要解决后返回主线 | 在当前学习记录留痕，重要结论同步到 progress.md |
| 未来研究方向 | 简要解释，不展开完整研究 | 写入 [IDEA_BACKLOG.md](../IDEA_BACKLOG.md)，记录来源和再次评估条件 |

不得因旁支问题无故改变当前主线。只有经路线复核、说明必要性并在 progress.md 记录决策，才可调整后续路线。

## 5. 动态测验与 Gate

### Session 内即时检查

使用短问答、预测、诊断或小操作及时检查理解与实操；结果用于调整讲解和练习，不替代正式 Gate，也不预先锁定后续测验难度。

### Substage 正式 Gate

每个 Substage 结束设置正式 Gate，至少覆盖：

| 维度 | 需要观察的证据 |
| --- | --- |
| 概念理解 | 能用自己的话准确说明当前已学概念 |
| 机制解释 | 能解释为什么、如何发生以及适用条件 |
| 实际操作 | 能在当前教学范围内完成任务并检查结果 |
| 新情境迁移 | 能将截至当前已学知识用于不同案例，并说明判断依据 |

题目不得超出当前教学进度。Gate 的新情境迁移维度与 Gate 完成后布置的外部 Transfer Task 都必须执行，不能相互替代。

第一次正式测验难度由教学模型根据此前学习表现确定；如果证据有限，先利用当前教学范围内的即时检查校准，并记录理由，不编造已有成绩。

此后每次正式测验前（包括补测）必须：

1. 询问学习者希望相较上一次正式测验“降低 / 保持 / 提高”难度。
2. 结合上一轮正式测验、实操与迁移表现，决定实际难度，不能仅按偏好机械调整。
3. 记录学习者选择、实际难度及其理由；若实际难度与选择不同，说明原因。尚未取得选择时不默认代填。
4. 核对所有题目仍在截至当前已学范围内，再开展测验。

Gate 前说明当前测验的任务与验收依据。Gate 后记录题目或产物链接、四维表现、必要提示、错误及修正、结论和下一步。区分“完成测验”和“通过验收”，不能因为答完或有代码就自动判定通过。

未通过时安排针对性补练与必要补测，保留原记录，不自动推进。Stage Gate 汇总本 Stage 的 Substage Gate、学习结果和实际产物，决定是否具备下一阶段条件；不提前编制全部阶段的考试。

## 6. 外部材料与 Transfer Task

每个 Substage Gate 完成后，必须在**当时实时检索**，选择 **1 个**与 Stage 0 至当前 Substage 已学内容直接相关、值得研究的最新外部材料，可来自：

- 新闻或真实市场事件；
- 实际量化案例；
- 研究资料；
- GitHub 项目或代码实现。

优先最新、权威、直接相关的内容；核对发布时间、事件发生时间或代码更新情况，区分事实、作者解释与待验证推断。不以模型记忆、预先静态清单或只看搜索摘要代替当时检索和原始材料核验。范围窄时选择可核验材料中最新且合适的一项，并说明相关性与选择理由。

不得只推荐阅读。配套一个简短 **Transfer Task**，要求学习者用截至当前已学知识进行分析、实操或判断，明确：

- 材料标题、来源链接、发布/更新日期、检索时间；日期无法确认时明确注明。
- 对应 Stage/Substage/Gate 与相关已学知识。
- 具体任务、预期交付物、检查标准与适当工作量。
- 当前状态、完成产物、下一次 Session 的检查与反馈。

Gate 完成后即执行此流程，不将 Gate 未通过当作省略迁移的理由；任务可针对已学内容与暴露的缺口设计。检索不可用或尚无可核验合适材料时，明确记录“待检索/阻塞”及原因，恢复条件具备后补齐；不得假称已实时检索或已布置合格任务。

下一次 Session 开始时，**必须先检查该 Transfer Task 的完成和应用情况，再进入新知识**。检查学习者是否能应用知识、解释判断与识别限制，而不只是是否阅读材料或提交答案。未完成、应用不足或任务仍待检索时，先补齐或处理缺口，记录反馈与后续动作，不跳过检查直接推进。

任务的当前状态只在 progress.md 维护；完整材料、分析或操作产物可放在 reports/ 中并由进度文件链接。初始化时尚无已完成 Gate，因此不提前选择材料或布置任务。

## 7. 动态路线复核

Stage 0–7 是主线框架，不是不可修改的死计划。进入重要 Substage/Stage 前，应综合：

1. 当前学习成果；
2. 实际研究结果；
3. 项目目标；
4. 工具与数据条件；
5. 最新量化实践；
6. 当前可用 AI 模型与工具能力。

复核当时按需要实时检索相关实践、工具文档与能力信息，明确已核验事实与尚待验证判断，不凭印象断言“最新”或“更好”。

当核心 AI 模型或工具能力明显升级时，重新审视已有方案；保留仍然正确的已确认内容，只修改确有必要的部分，并记录调整原因。新增模型、工具或积压想法本身不构成改线理由。

每次复核在 progress.md 记录日期、触发原因、依据与证据、保留项、变更项、理由及对下一任务的影响。即使决定维持路线，也应记录依据。只有需要改变路线、规则或想法归类时才同步修改对应文件，不整体覆盖有效历史。

## 8. 学习记录与维护闭环

Session/Gate/Transfer Task 产物出现后再按需要放入 reports/、notebooks/ 等目录，不提前制造空的学习成果。Session 记录至少说明任务、学习者表现、实践产物、即时检查、旁支问题与复盘；正式测验和迁移任务按上文补充证据。

每次 Session、Gate、Transfer Task 检查、关键决策或路线复核结束后：

1. 核对实际产物与结果，区分计划、尝试、完成和通过。
2. 更新 progress.md 的当前任务、已完成内容、下一任务、Gate、测验、Transfer Task、重要旁支问题、策略版本、模拟盘状态、关键决策与复核记录。
3. 新的未来方向写入 IDEA_BACKLOG.md；必要时更新 roadmap.md 或本规则文件，README 只同步入口和规则摘要。
4. 更新 progress.md 的最近更新时间，保留历史记录与证据链接。
5. 检查文件之间的目标、层级、工具路线、教学、测验、迁移和事实优先级是否一致。

策略版本必须对应真实策略产物；没有策略时写“未创建”。模拟盘状态必须对应真实记录；尚未开展时写“未开始”。不能将文档初始化计作 Stage、Substage、Session、Gate 或模拟盘已完成。
