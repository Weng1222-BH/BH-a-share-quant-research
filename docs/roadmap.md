# 动态学习路线图

## 目标与边界

从零学习 A 股量化，逐步完成数据分析、策略回测、科学验证、因子研究、机器学习预测、模拟盘验证，并形成 GitHub 与简历成果。

工具主线：**Python + AKShare + RQAlpha**；后期按需要引入 Qlib，暂不提前引入复杂交易系统。具体版本、接口、数据条件和能力在实际使用前核验。

本文件只维护路线与预期学习结果，不维护实际进度。当前状态、任务、Gate 与 Transfer Task 均以 [progress.md](progress.md) 为准；教学细则见 [operating_principles.md](operating_principles.md)，旁支想法见 [IDEA_BACKLOG.md](../IDEA_BACKLOG.md)。

## Stage 0–7 主线框架

以下为宏观目标与候选证据，不是已完成成果，不固定后续全部 Substage 或 Session。

| Stage | 名称 | 预期学习结果 | 可用于验收的产物方向 |
| --- | --- | --- | --- |
| 0 | 量化世界观 | 理解量化研究的基本问题、证据意识与研究流程 | 问题分析、机制说明、当前范围内的判断与复盘 |
| 1 | A股数据与基础收益分析 | 获取和检查基础数据，解释收益分析结果 | 数据说明、基础分析笔记与可复现结果 |
| 2 | 第一套完整策略与回测 | 将清楚的规则连接成完整回测流程 | 策略假设、规则、回测记录与结果说明 |
| 3 | 科学回测与偏差识别 | 识别偏差并用合适的验证方式审视结果 | 偏差检查、验证设计与对照结果 |
| 4 | 因子研究 | 从研究假设出发评估因子，解释证据与限制 | 因子定义、研究记录、验证结果与局限 |
| 5 | 多因子与机器学习预测 | 在已有研究基础上构建、比较和验证预测方案 | 基线比较、特征与目标说明、验证报告 |
| 6 | 模拟盘验证 | 检查研究方案在模拟运行中的表现及与回测的差异 | 模拟盘运行记录、异常与差异分析 |
| 7 | GitHub 与简历成果整理 | 将实际工作整理成可复现、可核验的公开成果 | 仓库说明、研究报告、证据链接与简历项目表述 |

Stage 7 可以整理此前积累的产物，但不能把规划中的策略、模型或收益写成真实成果。模拟盘验证不等于实盘验证；本主线不自动授权真实资金交易。

## 学习层级与规划粒度

**Stage → Substage → Session → Gate**

- 每个 Stage 根据学习结果动态拆分约 2–4 个 Substage；数量是规划参考，不是机械配额。
- 每个 Substage 包含若干 Session，Session 数量与安排随理解、实操和迁移表现调整。
- Session 内短即时检查用于及时发现缺口；Substage 结束时设置正式 Gate。
- Gate 至少覆盖概念理解、机制解释、实际操作、新情境迁移，题目不得超出当前教学进度；Stage 0 的实践与实操验收可以采用已学范围内的案例操作或判断，不强制提前编程。
- Stage Gate 用于汇总该阶段 Substage 的验收与实际产物，判断是否具备进入下一 Stage 的条件，不预设另一套超前试卷。
- 不一次性固定 Stage 0–7 的全部微观计划，只在接近开展时规划必要范围；候选计划与已完成事实分开记录。

学习时间预算以 progress.md 为准，Session 可以弹性安排，不以日历推进代替学习结果。

## 近期规划边界

初始化只建立项目管理系统，不执行 Stage 0 教学，不创建实际策略代码，也不预先布置尚未发生的 Gate 或 Transfer Task。

Stage 0 第一个 Substage 的目标、划分和 Session 由实际开始学习时规划；本文件不提前固定名称、课表或测验。正式规划时明确本 Substage 的预期结果、必要实践、Gate 证据与依赖，执行状态写入 progress.md。

## Gate 与外部迁移衔接

第一次正式测验难度由教学模型根据此前表现确定。此后每次正式测验前，先询问学习者希望相较上一次“降低 / 保持 / 提高”，再结合上一轮测验、实操和迁移表现决定实际难度，并记录选择与原因。

每个 Substage Gate 完成后，必须在当时实时检索，选择 **1 个**与 Stage 0 至当前 Substage 已学内容直接相关、值得研究的最新外部材料，优先最新、权威、直接相关的新闻或真实市场事件、实际量化案例、研究资料、GitHub 项目或代码实现。

材料必须配套简短 **Transfer Task**，要求用已学知识进行分析、实操或判断，并给出交付物与检查标准，不能只推荐阅读。下一次 Session 开始时先检查任务的完成和应用情况，再进入新知识；若未完成或迁移不足，先处理缺口，不跳过检查。

Gate 完成与 Gate 通过分别记录。未通过时保留测验与迁移任务记录，安排针对性补练，不自动推进阶段。具体记录要求及检索不可用时的处理见 operating_principles.md。

## 路线复核

Stage 0–7 是主线框架，不是不可修改的死计划。进入重要 Substage/Stage 前，根据以下信息重新评估后续路线：

1. 当前学习成果：概念、机制、操作、迁移的表现与缺口。
2. 实际研究结果：已有代码、实验、报告和验证证据。
3. 项目目标：学习、研究、模拟盘与成果展示的需求。
4. 工具与数据条件：可用性、质量、授权、维护与成本约束。
5. 最新量化实践：在复核当时检索并核验与当前范围相关的材料。
6. 当前可用 AI 模型与工具能力：能做什么、限制是什么、是否能改善当前流程。

核心 AI 模型或工具能力明显升级时，应触发路线复核。保留仍然正确的已确认内容，只修改确有必要的部分，不因为出现新工具就整体重写计划。

复核结果记录到 progress.md：日期、触发原因、证据或链接、保留内容、必要改动、不改动的理由（如适用）、对下一任务的影响及复核条件。涉及路线、教学规则或想法归类的变化时，同步更新对应文件，保留决策历史。

事实判定遵循 **GitHub 实际代码/结果 > docs/progress.md > 研究报告与 Session 产物 > 聊天记录 > 模型记忆**；路线表中的预期结果不构成完成证据。
